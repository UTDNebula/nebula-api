# API Architecture

Nebula API provides UTD data for others to use, including information on courses, professors, events, and more.

## API Overview

Here's a quick look at Nebula API.

### REST API

The Nebula API is a RESTful API. [What's an API? What does RESTful mean?](https://aws.amazon.com/what-is/restful-api/)

Currently, the Nebula API offers data for the following through its endpoints:

- Courses
- Professors
- Sections
- Grades
- Comet Calendar Events
- Mazevo Events
- Astra Events
- Club Events - provided by UTD Clubs
- Rooms
- Discounts

Docs for each of these endpoints can be found on [Our REST API Swagger page](https://api.utdnebula.com/swagger/index.html), which is generated from comments in the code.

> [!NOTE]
> Nebula API powers only UTD Trends and UTD Rooms. UTD Clubs and Notebook have their own API internal to their own projects. In addition, the Clubs endpoints are powered by the internal Clubs database.

All of this information (except for the clubs endpoints) is gathered with [API tools](https://github.com/UTDNebula/api-tools), which is responsible for scraping, parsing, and uploading the data to a Mongo database.

### How does Nebula REST API work?

When a user sends a HTTP request, [Gin](https://gin-gonic.com/) handles the request by matching the URL request to one of our routes. For example, if a user sends a `GET` request to `https://api.utdnebula.com/course`, that request goes to the course route, found in `rest/routes/courses.go`.

Then, Gin passes the request's arguments to the appropriate controller (in `rest/controllers`). These arguments are used for filtering and limiting data, so the user gets exactly what they want.

The controller uses those arguments with Mongo's Go Driver to construct a query filter and execute it against the Mongo database. This process gets the user the exact data they requested.

The Mongo database then fetches the requested data with filters and returns the data back to the controller. The controller sends the data back to Gin. The controller can also provides Gin an HTTP status code indicating the requests outcome (such as if it was successful).

Gin creates a HTTP response with the data and HTTP status code.

Finally, Gin sends the HTTP response back to the user.

## API Documentation

We currently use Swagger for our API documentation. Swagger automatically generates documentation for our API routes from comments in the code.

If you make any changes, make sure to run either the Makefile or build.bat to update the documentation.
